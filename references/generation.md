# 生成流程

## 1. 确定输入

读取实际视频对应的 Composition 入口、导出、fps、宽高、props 和裁切区间。记录源码文件 SHA-256 与视频 SHA-256。每项代码证据写相对路径及行号；视频证据写时间段和观察到的现象。

生成期的 Code + Video 用于确定评估对象与动作。评分期的输入是原作源码和复刻源码。原作入口及参数固定在隐藏清单；复刻入口、导出及 Composition 配置由提交资料提供。

## 2. 形成隐藏清单

每个对象记录稳定身份、时间范围和选择规则。文字以实际 JSX 文本为准，可允许空白归一化；SVG 以几何和上下文匹配；图片以素材引用和资源指纹记录。重复对象必须有可区分的上下文。

每个检查项记录属性、单位、容差和代码/视频证据。例如：答案卡片有缩放入场；高线比高度文字先开始渐显；三角形轮廓在指定区间绘制；光标透明度周期变化。

## 3. 解析和比较

对两份源码使用同一个白名单 AST 分析器，得到指定时刻的组件树和属性。解析本地 imports、props、数组生成、Sequence 局部帧和表达式依赖。保留源码出处。

对象定位先按内容、几何及上下文执行。选择器应允许等价写法，遇到多个候选返回歧义。指定采样网格与边界采样，写入隐藏清单并冻结。时序精度以实际采样步长为限。

属性检查分为：对象及内容、静态几何/样式、对象所绑定的动作、随时间变化的数值。函数名作为证据；分数比较作用到对象上的结果。移到无关元素上的正确公式不能满足目标对象检查。

## 4. 完成交付

评估包包含通用解析器、案例测量器、固定依赖、隐藏清单、标准数据和验证结果。生成草稿后，先校准误差阈值，再运行验证组。正式冻结前记录所有不支持的对象和属性。

标准数据供复核；评分仍读取、校验并解析原作源码。原作源码指纹变化时要求重新生成。重复运行对输入及依赖保持一致。
