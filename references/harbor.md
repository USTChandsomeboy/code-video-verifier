# 批量生成与 Harbor 接口

## 每条样本的生成依据

记录原作仓库、commit、实际工作文件指纹、Composition ID、注册入口、组件导出、fps、总帧数、画布、props、片段起点和视频 SHA-256。登记入口与真正的组件入口是两个字段。独立注册某个场景时，时间从该场景的零帧开始；目录中记录的原片时间不一定就是分析器的时间偏移。

自动静态解析能形成检查建议。逐项记录对象和动作所覆盖的时间段、源码证据与视频核对结果；未经视频核对的建议保持草稿。若导出、props、裁切或源码与视频对应关系不确定，保留具体原因，先完成明确的项目。

## 可测范围

把三个问题分开记录：是否找到正确对象、能否解析该对象的属性、现有检查是否覆盖目标能力。高宽比相同不证明 SVG 形状相同；属性会变化不证明运动曲线正确；spring 时间输入变化不证明阻尼等参数正确。针对目标能力选择实际实现的测量器，未覆盖的项目进入待补列表。

修改原作或复刻的函数、变量名与组件组织后，行为等价的表达应保留得分。对结构参数的检查标明其含义和适用实现；遇到另一种等价实现但当前无法证明时，记录未解析，不把实现名称相同当成行为正确。

## 校准产物

保存自对照、等价改写、定向错误、真实复刻的逐项结果。绑定错对象、缺失但存在同名无关文字、相同比例而顶点错误、只改 spring 参数、延迟挂载、未知分支各自需要适用的正反例。权重和容差在评价真实复刻之前固定。模板变化后重新校准并封存。

## Harbor 包装

agent 环境提供参考视频、空白工程与固定依赖。GT、评估代码、历史复刻和校准结果属于评估端。提交目录固定，并从 agent 容器复制到单独 verifier 容器。

依照选定 Harbor 版本校验 TaskConfig 与运行路径。独立 verifier 的镜像入口使用 `/tests/test.sh`；`/logs/verifier/reward.json` 的值只放数值，状态、原因和覆盖明细写到另一个文件。有效成绩可映射为 `reward=score/100` 并另存 `score_100`。解析失败或未生成完整规则属于评估错误，不能伪装成模型真实 0 分；空提交等明确无效提交可以记录 0 分及原因。

分别报告静态配置检查、本地 verifier 运行、Harbor oracle 容器运行、正式 agent 运行。只有实际执行的阶段才标为通过。

## 文件存储

参考视频和原作素材登记在内容哈希索引中。任务准备阶段使用硬链接、受控下载或存储挂载提供文件；同一文件在本地任务间不重复保存字节。跨机器传输只下载一次并校验哈希。任务包可保留独立评分代码，视频文件不提交到 Git。公开任务与隐藏评估资料分别打包。
